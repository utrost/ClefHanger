# Android test APK updates

The [native prerelease workflow](../../.github/workflows/native-prerelease.yml) publishes a directly downloadable APK to [GitHub Releases](https://github.com/utrost/ClefHanger/releases). It runs for native changes on `feat/flutter-rust-port` and can also be started manually. Each new workflow run uses Android version code `1000 + github.run_number`; rerunning the same run keeps its version. Android accepts an in-place update when the app ID, signing certificate, and version code meet its update rules.

Prereleases use one persistent **test** signing certificate. The private keystore is stored in the repository's `CLEFHANGER_TEST_KEYSTORE` Actions secret and an ignored, mode-600 local backup at `.local/signing/clefhanger-test.keystore`. Preserve a secure backup outside this checkout before removing it: GitHub secrets cannot be read back. The committed `tools/android/test-signing.sha256` pins the public certificate. The workflow refuses a missing or mismatched secret and checks the signed APK's certificate, app ID (`com.simiono.clefhanger`), version code, and Rust libraries before publication. Never commit the private keystore or its base64 encoding.

The earlier `clefhanger-android-debug` Actions artifact was signed with a runner-generated key. Android cannot install this new series over it. Uninstall that one test build, install the new prerelease APK, and keep subsequent prerelease installations in place. Uninstalling erases Android app-private progress; if needed, first export progress from the PWA and import it again in the Android app. There is currently no Android-to-file progress export.

To update, download the newer `.apk` asset from Releases on the phone and open it. Do not uninstall the existing prerelease. The new APK should replace it and retain its local data. An older build cannot downgrade a newer one. These test-signed APKs establish an updateable test series, not a production/Play Store signing identity. Switching to a different production certificate later would require a separate migration or reinstall decision.
